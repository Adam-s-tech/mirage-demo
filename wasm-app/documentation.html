Documentation de la démonstration OCR et vision avec un LLM miniature

Cette page explique ce que fait la démonstration, comment lire ses résultats, ce que les trois tests de référence montrent réellement, et pourquoi l’image analysée ne quitte pas le navigateur.

Comment se déroule une analyse

  1. Import. Vous déposez une image JPG, PNG ou WebP, ou vous la sélectionnez avec le bouton « Parcourir les fichiers ». Le fichier reste en mémoire dans l’onglet.
  2. Chargement du moteur. Au premier lancement, le navigateur télécharge le moteur cactus.wasm puis les poids du modèle mirage.cact (environ 22 Mo), mis en cache ensuite.
  3. Inférence locale. L’image est redimensionnée à 1024 pixels sur le grand côté, convertie en pixels RGB et transmise à cactus_describe() dans le moteur WebAssembly.
  4. Lecture des résultats. Les boîtes, masques, étiquettes et zones de texte sont dessinés sur l’image. Les panneaux listent la scène, les objets, les textes détectés et les relations.
  5. Export. Le JSON brut reste affiché tel quel. La copie reprend ce JSON sans modification ; le téléchargement ajoute un bloc de métadonnées séparé.

Deux modes d’exécution

Mode Où tourne l’inférence Prérequis Usage conseillé
WebAssembly (principal) Dans l’onglet, via cactus.wasm Un navigateur récent, environ 22 Mo de téléchargement au premier lancement Démonstration, formation, test de documents sensibles
Serveur local Sur votre machine, via cactus mirage describe Bun et la CLI Cactus installée Comparaison, automatisation en ligne de commande

Les commandes exactes sont décrites dans le guide d’installation.

Confidentialité et requêtes réseau

En mode WebAssembly, l’image ne quitte jamais le navigateur : elle est chargée depuis un objet local (blob:), dessinée dans un canevas, puis traitée par le moteur inclus dans la page. Aucun outil de mesure d’audience, aucun compte et aucun stockage distant ne sont utilisés.

La page publiée sur GitHub Pages télécharge les poids du modèle depuis Hugging Face lors du premier usage. Cette requête ne transporte aucune image et ne récupère que le fichier mirage.cact. En local, le petit serveur wasm-app/serve.ts télécharge ce même fichier une fois et le sert depuis wasm-app/models/.

Pour vérifier ce comportement : ouvrez l’onglet « Réseau » des outils de développement, lancez une analyse, puis constatez qu’aucune requête ne transporte les pixels. La note complète est dans docs/confidentialite.md.

Limites connues

  • La démonstration analyse des images, pas des PDF : il faut convertir une page en image avant l’analyse.
  • L’interprétation textuelle est produite par le modèle en anglais ; l’interface est en français, mais ce paragraphe n’est pas traduit automatiquement.
  • Les scores de confiance varient d’une image à l’autre et ne constituent pas une garantie d’exactitude.
  • Les petits textes, les noms propres et les logos serrés sont les cas les plus fragiles en OCR.
  • Cette démo ne remplace pas un OCR comptable spécialisé ni un grand modèle multimodal pour une extraction contractuelle.
